## 2024-05-24 - Avoiding NumPy Overhead in Hot Loops
**Learning:** Instantiating `numpy` arrays and using `numpy` mathematical functions (like `np.sqrt` or `np.mean`) inside a per-frame hot loop (e.g., live computer vision inference) introduces significant overhead compared to using native Python structures (tuples) and standard library math (`math.hypot`, `sum()/len()`). The cost of creating array objects repeatedly outweighs the vectorized benefits for small, single-calculation data points per frame.
**Action:** When calculating simple Euclidean distances or small aggregations (e.g., window sizes <= 10) in per-frame computer vision or extraction loops, always use native Python tuples and the `math` library instead of `numpy`. Only use `numpy` when operating on large, pre-allocated batches of data.
