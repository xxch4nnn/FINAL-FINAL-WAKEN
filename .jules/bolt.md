## 2024-04-28 - Pre-compute virtual keys geometry
**Learning:** In the `main_runtime.py` file, the 3D geometry points for the virtual piano keys were being generated dynamically inside the per-frame hot loop. This was causing unnecessary memory allocations and looping on every frame just to build static geometry arrays before projecting them to 2D using `cv2.projectPoints()`. By pre-computing this 3D geometry array (`keys_3d`) outside the loop, we eliminate repeated object allocations.
**Action:** When working with AR/CV overlays, always analyze if 3D marker/geometry point arrays are static over time. If they are, hoist the creation of those numpy arrays outside the main processing loop and batch API calls (e.g., using `.reshape()` and passing batched arrays to `cv2.polylines`) to reduce overhead.
