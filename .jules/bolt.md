## 2024-04-22 - Optimize CV per-frame processing hot loops
**Learning:** Using `np.array` and `np.mean`/`np.sqrt` in Python hot loops (like processing MediaPipe coordinates every frame) creates excessive instantiation overhead, context switching to C++, and garbage collection that slows down the real-time CV pipeline. Native Python operations like `tuple()`, `sum()/len()`, and `math.hypot()` are significantly faster for small, high-frequency scalar math.
**Action:** Always favor native Python primitives (tuples instead of numpy arrays) and `math` module functions (`math.hypot`) over numpy arrays for isolated per-point coordinate math inside `process_live` or CV render loops. Use Numpy when vectorization across large arrays is possible, but avoid it for per-point iteration.
