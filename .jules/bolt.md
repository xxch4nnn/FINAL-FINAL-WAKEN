## 2024-04-08 - [Optimize OpenCV Projections & Allocations]
**Learning:** Found that invoking `cv2.projectPoints` and `cv2.polylines` repeatedly inside an inner loop causes significant Python-to-C++ context switching overhead, slowing down the frame processing loop. Additionally, repeatedly allocating static camera intrinsic matrices (`K`, `D`) generates unnecessary garbage collection pressure. OpenCV drawing functions like `cv2.polylines` can accept a batched sequence (e.g. `list(pts_2d)` when reshaped appropriately), allowing us to vectorize multiple shapes in one call.
**Action:** Always precompute static shapes (like virtual piano keys) into a single batched NumPy array, project them entirely using one `cv2.projectPoints` call, and render them using batched arguments to `cv2.polylines`. Move constant parameters (like intrinsic matrices) outside of real-time `while` loops.
