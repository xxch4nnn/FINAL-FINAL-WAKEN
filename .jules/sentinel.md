## 2024-05-24 - Insecure Deserialization in ML Pipeline
**Vulnerability:** The project was using `joblib` and `pickle` to load the machine learning model, scaler, and features in both `main_runtime.py` and `src/runtime/vision_engine.py`. Loading models using `pickle` or `joblib.load` directly from `.pkl` files executes arbitrary code if the file is tampered with, leading to arbitrary Remote Code Execution (RCE).
**Learning:** Legacy ML pipelines often default to `joblib` or `pickle` for convenience when saving artifacts. We learned that the `xgboost` native `.json` model format combined with basic `json.load()` for supplementary artifacts provides a fully secure serialization path without losing functionality.
**Prevention:** Never use `pickle` or `joblib` to deserialize machine learning artifacts, especially in distributed or runtime environments. Always use native, text-based serialization formats like JSON (e.g., `model.save_model("model.json")`) and standard JSON parsers for metadata like scalers and features.
