## 2024-05-09 - [CRITICAL] Insecure Deserialization via pickle/joblib
**Vulnerability:** The application uses `pickle.load()` and `joblib.load()` to deserialize Machine Learning models, scalers, and selected features in `src/runtime/vision_engine.py` and `main_runtime.py`. This leads to a critical Remote Code Execution (RCE) vulnerability if a malicious actor replaces or provides tampered `.pkl` files.
**Learning:** Legacy ML saving mechanisms (`joblib.dump`, `pickle.dump`) serialize code paths and state, inherently running any malicious code embedded within upon load. This vulnerability pattern is specific but common in ML applications transitioning to production. Native serialization formats (like XGBoost's `.json` saves) and raw data formats (`.json` for scalers/features) are required for safety.
**Prevention:** Always use native and secure serialization mechanisms for ML artifacts. Scikit-learn scalers and feature lists must be serialized to JSON, and XGBoost models must use `.json` saving/loading (`save_model()` and `.load_model()`). Never use `pickle` or `joblib` for runtime artifact loading.
