## 2024-05-04 - Fix Insecure Deserialization of ML Artifacts
**Vulnerability:** The codebase was actively using `pickle` and `joblib` to deserialize machine learning artifacts (models, scalers, and feature lists) in its primary entry point (`main_runtime.py`) and vision engine (`src/runtime/vision_engine.py`). This allows arbitrary code execution if an attacker supplies maliciously crafted `.pkl` files.
**Learning:** Legacy serialization tools like `joblib` and `pickle` are common in ML pipelines but they do not guarantee secure deserialization. It is crucial to use standard, explicitly safe mechanisms when artifacts originate from an external directory.
**Prevention:** Use strictly formatted or platform-native serialization such as `.json` or `.h5`. XGBoost provides `save_model`/`load_model` methods for its artifacts, which natively store components in `.json`. General variables (like feature lists) and simple class states (like scalers) can safely be mapped into pure JSON structs.
